- **Delivered:** `scripts/noramedi-frontend-deploy.sh` — `deploy` / `rollback` / `verify` subcommands plus a real `--dry-run`. One script, not a second deployment abstraction; the backend script remains authoritative for the backend and is unchanged.
- **Promotion semantics — stated, not upgraded:** a **TWO-STEP SAME-FILESYSTEM RENAME PROMOTION** (`mv dist <preserved>` then `mv dist.next dist`), **near-atomic, NOT a single atomic exchange**, with a very short interval in which `dist` does not exist. Same-filesystem is *enforced* by device comparison (a cross-device `mv` would silently degrade to copy-then-delete). A failure of the second rename triggers a **bounded best-effort restoration**, so production is never left without a live bundle — and both outcomes produce distinct operator messages.
- **Rollback contract:** deterministic. The exact preserved path is recorded at deploy time in `.noramedi-frontend-release-state` (written **only after** a successful promotion) or named with `--from`; with neither, rollback **aborts** rather than guessing from directory ordering. The current bundle is preserved before replacement, so a rollback is itself reversible. **The script contains no `rm` and no deletion primitive at all** — even `--clean-staging` moves a stale `dist.next` aside.
- **Release traceability:** no frontend release marker existed anywhere (`release.json`, `__RELEASE__`, `VITE_*SHA*`, `vite.config.ts` `define:` — all absent), so `dist/release.json` (`releaseSha`/`builtAt`/`builtBy`/`task`) displaces no rival contract. It carries no path, hostname, environment value or secret, and the suite pins its field count so a future addition turns a test red. A dirty worktree is refused without `--allow-dirty`.
- **Backend/frontend skew reported, not forced:** `FRONTEND_RELEASE_SHA` / `BACKEND_RELEASE_SHA` / `RELEASE_SHA_MATCH = YES|NO|NOT_APPLICABLE`. The backend value comes from the **running process** (`pm2 jlist` → `pm2_env.RELEASE_SHA`, the same path `noramedi-deploy.sh:139-154` uses) and is **never fabricated from local git state**, which would report what is checked out rather than what is running and would hide real skew.
